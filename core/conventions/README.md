# core/conventions/

This folder contains **human-readable authoring guides** - one per component type. They explain what each component is for, how to think about writing one, and common pitfalls. They are not assembled into prompts and not referenced by blueprints.

When in doubt about how to write a component, start here. When you need the exact required fields and sections, refer to the corresponding schema in `core/schemas/`.

## Files

| File               | Describes                                                       |
| ------------------ | --------------------------------------------------------------- |
| `persona.md`       | What a persona is, when to write one, how to structure it       |
| `skill.md`         | What a skill is, activation patterns, scope decisions           |
| `shared-blocks.md` | What a shared block is, reuse logic, when not to use one        |
| `output.md`        | What an output template is, file organisation, naming           |
| `context.md`       | The `context` component type (stub - not yet implemented)       |
| `prompt-schema.md` | Index: where to find each component's convention doc and schema |
